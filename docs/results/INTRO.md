# Benchmark results

This page is generated by `benchmarks/make_report.py` from the files in `docs/results/` (written by `nam_bench --json` and `two_instance`).

## Measurements

Processing time of `Processor::process` for one block, at buffer sizes of 64, 128, 256 and 512 samples and host rates of 44.1, 48 and 96 kHz,
for A2-Full and A2-Lite. Model: `tests/data/test-amp-and-cab.nam`. The second model, `a2-example.nam` (NAM Core example), is listed in the
detail tables and gives the same times: the processing time of an A2 model depends on its size (A2-Full or A2-Lite), not on its weights.

The baseline is the NAM Core A2 fast path (commit `d3189ed`).

## Method

- **Input.** Two generated sine waves (220 Hz at 0.25, 1230 Hz at 0.10). The processing time does not depend on the input: the arithmetic per
  sample is fixed and denormal numbers are flushed to zero. A guitar recording gives the same time.
- **Interface.** Both implementations process buffers of 64-bit floating-point numbers (the NAM Core interface). The conversion to 32-bit
  inside `process` is included in the time of namturbo and is below the resolution of the measurement.
- **Timing.** Each block is timed with the steady clock of the operating system. The first pass over the signal is excluded. A run processes
  3 s of audio; there are 5 runs. The tables give the median over the runs of the 50th percentile (p50) and of the 99th percentile (p99) of the block times.
- **Speed-up.** In each run, namturbo and NAM Core process the same signal one after the other. The speed-up of a run is the p50 of NAM Core
  divided by the p50 of namturbo; the tables give the median over the 5 runs.
- **Thread.** The benchmark thread is pinned to one logical core. On the Intel processor, which has performance and efficiency cores, the core is a
  performance core.
- **NAM Core build.** Same compiler as namturbo, release configuration, A2 fast path enabled, AVX2 and FMA code generation (`/arch:AVX2` for
  MSVC, `-mavx2 -mfma` for clang-cl). NAM Core uses Eigen, which uses AVX2 and FMA only if the compiler generates them. Without these flags
  NAM Core is slower: on the AMD machine, A2-Full at buffer size 64 takes about 93 us instead of 66 us, and the speed-up of namturbo is 4.9x
  instead of 3.5x. The tables use the faster build.
- **Sample-rate conversion.** NAM Core has no sample-rate conversion. The comparison is therefore made at 48 kHz only. At 44.1 and 96 kHz
  the tables give the load of namturbo, including the conversion.

## Machines

| | AMD | Intel |
|---|---|---|
| Processor | AMD Ryzen 5 7535HS (laptop) | Intel Core Ultra 5 245K (desktop, 6 performance and 8 efficiency cores) |
| Operating system | Windows 11 | Windows 11 Pro |
| Compilers | MSVC 19.44 (Visual Studio 2022), clang-cl 19.1.5 | MSVC 19.44 |
| Pinned to | logical core 2 | logical core 0 (performance core) |

The machines were not used for other work during the runs. Results on other processors, operating systems and compilers differ. The benchmarks were run on Windows only.

On the Intel processor an efficiency core is slower: at buffer size 64 and 48 kHz, A2-Full needed about 1.9 times the time of a performance core.

## Repeating a run

    cmake -S . -B build -DNAMTURBO_BASELINE=ON
    cmake --build build --config Release
    python benchmarks/run_report.py build/Release/nam_bench.exe results --core 2 --tag mymachine

`--core` pins the thread; on a processor with different core types, a performance core is selected. The baseline requires the NAM Core submodule
(`git submodule update --init --recursive`) and Python 3.
